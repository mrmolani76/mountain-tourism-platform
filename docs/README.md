# docs/ — Project & Feature Documentation

> **Rule**: `docs/` holds ONLY project-related and new-feature-related info. All tracking (work items, bugs, change reports, sessions, dashboard) lives in `work/` — do not put that here.
>
> **Start here for the repo:** root [`README.md`](../README.md).

## Index

| File / Folder | What it is |
|---|---|
| [`../README.md`](../README.md) | Repo entry point — what this project is, stack, quick start, links |
| `PROJECT_GUIDE.md` | Full project guide — architecture, stack, setup, API, day-to-day ops (create when the app scaffold lands) |
| `DEPLOYMENT.md` | Deployment procedures (create when deployment is defined) |
| `features/` | New-feature related info (one MD per feature) |
| `detailed/` | Phase-wise / module-wise detailed documentation |
| `archive/` | Old / obsolete docs (single source of current truth stays in `work/`) |

## Where tracking lives

| What | Where |
|---|---|
| Work plan / kanban (todo/inprogress/completed) | `work/PLAN.md` + `work/todo/`, `work/inprogress/`, `work/completed/` |
| Master dashboard (all counts) | `work/SUMMARY.md` |
| Bugs (full cycle + backlog INDEX) | `work/bugs/` |
| Change reports | `work/changes/` |
| CI failure reports | `work/ci-reports/` |
| Session handoff | `work/MEMORY.md` |
| Work templates | `work/TEMPLATE.md`, `work/bugs/BUG_REPORT_TEMPLATE.md`, `work/changes/CHANGE_REPORT_TEMPLATE.md` |
