# Change Report: Run Nuxt Docker Development With HMR

- **Date**: 2026-11-27
- **By**: Copilot
- **Change ID**: 125

## 1. Summary
Added a dedicated Nuxt Docker development service and fixed live reload for Windows bind-mounted source files.

## 2. Before
- `frontend/Dockerfile` had no dedicated development target.
- The Nuxt dev service did not have explicit file-watch polling for Windows Docker bind mounts.
- The Compose usage comment pointed to `http://localhost:3000`.
- A source edit appeared inside the container but did not update the browser after HMR or a full reload.

## 3. After
- `frontend/Dockerfile` has a `development` target that prepares Nuxt and runs the dev server.
- `docker-compose.spa-dev.yml` starts only the SPA dev service, mounts the source, and enables `NUXT_DOCKER_WATCH_POLLING`.
- `frontend/nuxt.config.ts` enables Vite polling at a one-second interval only when that environment variable is true.
- The documented browser URL is `http://lab.local.mtmtp.local:3000/`.

## 4. Reason
The user requested Docker-based development with hot reload and specified the tenant hostname. Vite's default watcher did not reliably detect edits on the Windows bind mount.
